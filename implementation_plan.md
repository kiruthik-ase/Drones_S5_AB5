# UAV B-Spline Trajectory Planner & Dynamic Simulation

This document outlines the implementation plan for building a "perfectly working" simulation of the UAV trajectory planner described in the paper *“Optimal Trajectory-Planning of UAVs via B-Splines and Disjunctive Programming”*, combined with a dynamic flight controller.

## 🏆 The "Perfectly Working" Stack

To guarantee a reliable, easy-to-run, and mathematically robust simulation without the notorious complexities of ROS/Gazebo, we will use the following stack:

1.  **Language:** Python 3 (standard for modern optimization and ML).
2.  **Physics & Visualization:** **PyBullet**. It is incredibly fast, easy to set up, and reliable for rigid body dynamics like quadrotors.
3.  **Optimizer:** **Gurobipy** (Python API for Gurobi) or an open-source MILP solver.
4.  **Controller:** **Geometric Tracking Controller**. This mathematically leverages the smooth $C^2$ acceleration reference generated by the paper's B-spline planner.

## 🏗️ Proposed Architecture

The system will be built in a modular fashion to ensure we can debug the math independently of the physics.

### 1. Mathematical Planner Module (`planner.py`)
This module implements the core paper:
- **B-Spline Evaluation:** Functions for Cox-de Boor recursion, generating basis functions, and calculating 1st/2nd/3rd derivatives.
- **Optimization Formulation (MILP):** Sets up the Receding Horizon problem.
- **Objectives:** $J_1$ (Length/Target), $J_2$ (Altitude), $J_3$ (Active knots sparsity).
- **Constraints:** Velocity, acceleration, continuity.
- **Disjunctive Constraints (Big-M):** Terrain tangent planes and Polyhedral obstacles.

### 2. Low-Level Controller Module (`controller.py`)
- **Geometric Controller:** Takes the instantaneous reference state $p_d(t), v_d(t), a_d(t)$ from the B-spline.
- Computes desired thrust and body torques (or motor RPMs) to command the PyBullet drone.

### 3. Simulation Environment Module (`simulation.py`)
- Initializes the **PyBullet** environment.
- Spawns the Quadrotor model, static/dynamic obstacles (cuboids), and terrain.
- Runs the main loop:
  1. Get drone state.
  2. Run Planner (e.g., every 1 second).
  3. Run Controller (e.g., every 0.01 seconds) to track the planned B-spline.
  4. Step Physics.

## 🚀 Implementation Phases

To ensure this works perfectly, we will build it iteratively:

### Phase 1: Core Planner (Kinematic Only)
- Implement the B-spline math and MILP formulation.
- Test it with a simple start-to-goal scenario (no obstacles) and plot the $C^2$ trajectory in 3D using Matplotlib to verify the math perfectly matches the paper.

### Phase 2: Environment & Obstacles
- Add Big-M constraints for Static Obstacles and Flight-Prohibited Zones.
- Add Terrain Tangent-Plane constraints.
- Verify avoidance behavior in plots.

### Phase 3: PyBullet Integration & Controller
- Set up PyBullet with a standard quadrotor model.
- Implement the Geometric Controller.
- Connect the Planner (Phase 2) to generate waypoints on the fly, and the Controller to fly the drone in the PyBullet world.

## Verification Plan

### Automated Tests
- Run math validations to ensure $a_{max}$ and $v_{max}$ are never violated by the B-spline outputs.
- Verify that the junctions between receding horizons maintain $C^2$ continuity.

### Manual Verification
- Visual inspection of the PyBullet simulation to ensure the quadrotor physically avoids the spawned obstacles while successfully reaching the target.
- Compare our velocity/acceleration plots against Figures 5-8 in the paper.
